Platform & architecture
Spec 02 · The platform call

Native, and one app.

v2's biggest change: Rook ships as a native iPhone app with direct push, not a PWA — and it is declared the one surface. Nothing else gets built as a separate app for FM once Rook is live.

The platform call

Expo (React Native), custom dev client, TypeScript end-to-end. Weighed honestly against pure SwiftUI: shared zod schemas and API types with the server — one brain, two runtimes; Cursor productivity is highest in TS; EAS builds ship through TestFlight internal distribution (FM + 3, bundle id capital.citadel.rook, no App Store review friction); native modules where it matters — speech, push, keychain. SwiftUI remains a licensed future rewrite of the shell: the server contract is UI-agnostic, so nothing is lost by starting in Expo.

Push is direct APNs from argonaut (node-apn, token-based .p8) — no Expo gateway, no Firebase, no third-party transit. Payloads are generic — "2 criticals await", never matter names — and the tap opens the app, which pulls detail over the tailnet. Channels: T-48/24/3 escalations, staged-item nags, freshness alarms, ack/verify events, the 07:00 queue summary. Telegram mirrors as redundancy.

One app to rule them all

v2 ships the board, dispatch, capture and voice. The same app then absorbs, as read surfaces: the daily briefing and digests (v2.1), matter context packs and the 8787 mailbox excerpts (v2.1), agenda PDFs and Reference-Library lookup (v2.2). The rule: Rook renders other systems; it never re-implements them — and nothing else gets built as a separate surface for FM once Rook is live.

Unchanged from v1: Dropbox canonical, SQLite operating; a 30-day parallel run before authority inverts; Tailscale identity with the six-row device map; events append-only with the five proof fields; the _ROOK/ file contract for agents — now plus cards/.

Explicit non-goals, v2

Not a document editor; not a CRM; no public exposure; no autonomous sending; no privileged documents stored on-device — references and excerpts only, purged on lock; no Android yet; CarPlay deferred — the Siri Shortcut "Ask Rook" covers the car.

Spec 03 · Decision option cards

Tick the box.

The universal ruling pattern. FM already governs by option paper and checkbox — B005 was a five-option paper; the 13 Aug burn-priorities went out as "FM checkbox, executed". Rook makes that pattern native, categorised and tabular.

Structure

An Option Card belongs to an item and contains categories — named groups such as Funding · Legal · Timing — each holding option rows rendered as a table: checkbox, label, consequence or cost, and a note icon. Card-level config: select: single | multi | per-category, requires_text, allow_custom. A free-text field is always present — "or in your own words" — and a per-row note lets any tick be qualified: "yes, but capped at…".

Submitting is a decided event whose proof captures the exact ticks and text verbatim, and the ruling lands in _ROOK/decisions/ as structured YAML and prose — sweeps and agent sessions ingest it with no new code.

Three authors

Machine agents write _ROOK/cards/ROK-xxx.card.md — YAML frontmatter defines categories and rows, the body gives context; exactly the B005 five-option-paper pattern, now machine-renderable. The assistant drafts a card from an item's context on request — "give me options on Connal" — marked assistant-drafted, sources shown. Humans compose quick cards in-app. The 07:00 push summarises: "6 cards await ticks."

Seamlessness bar — acceptance, not aspiration

Push → card rendered under 2 seconds on tailnet · tick + submit in ≤ 3 taps · offline ticks replay losslessly · every tick visible in the Dropbox ledger within 60 seconds of reconnect.

Voice & the models
Spec 04 · Ask Rook

Say the word.

A voice you can talk to hands-free, plumbed into the model fleet the group already runs — an efficient OpenRouter-sourced frontier model for conversation, Opus 5 for the grunt work, and a deterministic router between them.

The voice pipeline

Push-to-talk on every screen, a hands-free session mode, and a Siri Shortcut. On-device STT → text over the tailnet to the gateway → streamed reply → on-device TTS, sentence-chunked with barge-in. Audio never leaves the phone; only text transits, and only to the tier the matter allows.

Voice can read the queue — "what's critical today?" — open and summarise an item, take an amendment note, draft a dispatch or an option card (staged), and defer or tick with spoken confirmation. Voice cannot release dispatches or close criticals — those stay on-glass taps.

The assistant's hands

Function-calling against the Rook API, allow-listed: query_items · get_item · add_amendment · stage_dispatch · draft_card · defer_item · tick_option(confirm). Every call is logged as an event with actor: assistant(model); anything beyond the list is refused by the server, not the prompt. The assistant may stage. It may never release, send, or widen its own tool list.

The gateway — two tiers and a router

ConversationKimi K3 via OpenRouter — the efficient frontier model the fleet already trusts as "the eyes", confidentiality gates in standing doctrine; fallback MiniMax M3 (1M context) for very long Q&A. Voice chat, queue Q&A, item summaries, transcript triage. Non-privileged matters only; answers cite item ids; load-bearing claims are marked for verification.
GruntOpus 5 (Anthropic API), detached jobs — dispatch bodies and option cards drafted from raw context, nightly board synthesis, meeting links → staged items, long adjudications. Full context allowed including privileged; privileged outputs render only to cleared roles.
RouterDeterministic rules, not a model: privileged → Opus only · voice/chat → Kimi · >200k context → MiniMax · draft/author → Opus. Every call priced into _ROOK/ledger/llm.jsonl — the AI spend ledger the audit said doesn't exist, started here.

The hard boundary

Privileged matters go to OpenRouter never — enforced in the router by matter flag and proven in CI with a canary item on every build. Gateway keys live server-side in the keychain: never in Dropbox, never on the phone, never in the repo.

Default voice brain ships as Kimi K3; the switch to MiniMax stays server-side. Voice is FM-only in v2; the team follows in v2.1.

Spec 05 · Data model & two-way sync

The decision object, at last.

Ten tables. One rule: events are append-only — supersede, never overwrite.

The store (SQLite · Drizzle · zod-mirrored)

itemsid, legacy id (R-/D-series preserved), kind, matter, lane, title, body, severity, status, owner, due, raised, source ref, privileged flag
context_refsper-item links — Dropbox paths, Gmail threads, calendar events, pinned quotes — every one a tappable deep link, auto-resolved by the importer (P16)
amendmentsnotes, corrections, questions — authored, timestamped, dictation-friendly
dispatchesto agent or person · body · channel · staged → released → acknowledged → done → verified · release token · proof ref
eventstimestamp · actor · transition · proof · verifier — the audit's five fields, on every state change
option_cards · groups · rowscard (select mode, requires_text, authored_by, state) → categories → rows: label, consequence, selected, note, custom flag
card_responsesactor, timestamp, selections as structured data, free text verbatim, event ref
assistant_logtier, model, tool calls, tokens in/out, cost NZD, item refs — feeds the spend ledger
devices · healthperson, APNs token, push prefs, last-seen · freshness per source: sweep, syncd, telemetry

Item statuses: open → decided → staged → dispatched → acknowledged → done → verified → closed. Nothing is deleted; supersession is a status, and prior text lives in the ledger.

Inbound · machines → Rook

board.json
Upsert items by legacy id — never clobbering fields Rook owns.
cards
Agent-authored option cards render natively; superseded cards close themselves.
digests · agendas
Attach as matter context; feed the Today strip.
acks · run-log tail
Agent acknowledgements flip dispatch state; sweep freshness feeds the banner.

Outbound · Rook → the fleet

_ROOK/decisions/
One markdown file per ruling — five-field frontmatter, ticks as YAML and prose. Sweeps ingest rulings with no new code.
_ROOK/dispatch/<agent>/
Instruction inboxes; agents ack by writing a file back. One doctrine page makes every session check its inbox at wake.
people
Scoped Rook view + optional gmail_sa draft for one-tap send + Telegram ping. Rook itself never emails anyone.
_ROOK/ledger/
Continuous JSONL mirror of events + the llm spend ledger + nightly DB snapshot — the record survives any machine.

Six screens
Spec 06 · One thumb, or no hands

Six screens, no more.

44-point touch targets, dark mode for the 02:54 decisions, a push-to-talk button on every one of them.
1 · Today — the triage stack.

Freshness banner, then cards hardest-gated first: criticals ≤ 72h, staged-unreleased with age badges, open option cards, new since last visit. Swipe right = decide; swipe left = defer; long-press = delegate to a person or agent. Three actions, one thumb.

2 · Queue — the D-series, operable.

Categorised and tabular: filter by matter, lane, severity, status, owner. Bulk checkbox mode — select many, defer / close / supersede once.

3 · Item — everything about one thing.

Current statement · pinned context (quotes, docs, mailbox excerpts via 8787, the calendar entry) · the human-readable event ledger · amendments with voice capture · its option card, rendered · every referenced folder, file and thread a live link — tap to open in Dropbox or the tailnet preview · actions: decide, amend, stage dispatch, mark verified — which demands a proof reference.

4 · Dispatch — the heart of it.

Staged: everything awaiting release, grouped by recipient, age badges, a Release button — FM only, token written, channel fired. In flight: released items awaiting ack, done, verify; overdue acks flagged. The direct fix for "a completed document waiting on a release decision."

5 · Matters — the fronts at a glance.

One card per front: status line, next hard date, seven-day activity spark, open cards and staged counts, link to the workstream context file.

6 · Pulse — the numbers the next volume quotes.

Decision latency (p50/p90), release latency, queue burn-down, staged-age histogram, verified-versus-claimed, freshness history — and now the AI spend line, straight from the gateway ledger.

Plus global search, quick capture — dictate a thought, file it to a matter, ten seconds — and "Ask Rook" from anywhere, including the lock-screen Siri Shortcut.

Spec 07 · Cursor-ready

Twenty-four days, six gates.

Monorepo: apps/mobile (Expo), apps/server, apps/web, packages/shared. Repo FM1983/rook, private. Each phase ends usable, each gate is runnable — "looks good" is not a test.

The phases

0 · Steel
d1–2
Monorepo, schema, tailnet serve, identity, health, APNs hello-world. Gate: a generic push arrives with the app closed; the tap opens the app; /api/health over tailnet shows identity.
1 · Mirror
d2–6
Importer + ingest; native Today/Queue/Item/Matters read-only; SSE; freshness banner; offline read cache. Gate: a sweep-written red flag on the phone in under 60s; an airplane-mode reopen still shows the queue.
2 · Decide
d6–11
Option Cards end-to-end; decide/defer/amend; quick voice capture; offline action queue; bulk checkbox mode. Gate: an agent-authored card is ruled in a lift; the .md ruling appears in Dropbox with the exact ticks; a sweep reflects it next cycle.
3 · Dispatch
d11–15
Staging, tokened release, agent inbox/ack loop, draft + Telegram channels, aging nags, T-48/24/3 push escalations. Gate: a test agent acks by file and state flips on the phone; a stale staged item nags exactly once daily.
4 · Voice
d15–20
Gateway, two tiers, router, spend ledger; push-to-talk and hands-free; assistant tools; Siri Shortcut. Gate: "what's critical, open the second one, note this, draft the dispatch" — completed without touching glass; the privileged canary provably never reaches OpenRouter; every call priced.
5 · Prove
d20–24
Verify flow, Pulse, ledger mirror, cross-alarming watchdogs, role scoping, TestFlight to the team. Gate: the 30-day parallel run starts; a killed daemon is alarmed within ten minutes.

Security — the v2 annex

Everything from v1 stands: tailnet-only, ts.net TLS, privileged matters excluded at the query layer, the immutable ledger, no secrets in the repo. v2 adds: APNs payloads carry zero content beyond counts and generic labels. The on-device cache excludes privileged bodies — references only, Face ID app lock, purge on role change. Gateway keys server-side only; the OpenRouter key arrives from FM directly and never touches Dropbox. Voice transcripts stored only when explicitly saved. The assistant cannot release, send, or widen its own tool list.

Definition of done

FM clears a real week from the phone; ≥ 80% of that week's decisions exist in Rook before any sweep infers them; zero staged items silently older than 72 hours; and the next Pulse quotes Rook's numbers — including the first real AI spend figures the estate has ever had.

Design: bone paper, ink, Citadel green as the only accent, rust for criticals; Archivo with tabular numerals; Fraunces for the wordmark alone. Tokens shipped as a file and consumed literally.
