Executive summary

Build the control plane first.

Three volumes of Lightspeed reached the same verdict: AMBER. The daily briefing machine is dependable and, in July, prolific — 362 artifacts in a fortnight. But it is a cockpit, not a control plane. It cannot run a weekly operating review from data, it stopped measuring itself after 3 July, and the one operator it exists to relieve is still the hidden integrator. The Operating Doctrine's standing instruction is unambiguous: "Build the control plane first. Without it, every other layer turns into clever chaos." This plan follows that instruction to the letter.

The work is organised into four phases across eleven weeks, from 16 July to the doctrine's 30 September leverage deadline. Phase 0 makes the machine tell the truth about itself. Phase 1 builds the canonical matter registry — the single load-bearing artefact everything else hangs from. Phase 2 adds routing, the first playbooks and the governance the Stella incidents demand. Phase 3 deploys the six monitors, un-freezes Notion, and measures the move from 2.8× to 5×. Each phase has an exit gate; nothing advances until the gate is met.

Phase 0
Phase 0 · Week 1 · 16–25 July

Stabilise & tell the truth.

A machine that cannot see itself cannot be scaled. Fix the instruments first.
0.1 · Honest telemetry
Infra

Restore the pipeline counter that went silent after 3 July. Replace the hard-coded errors_today = 0 with a real count off daily/_errors. Add per-service health (citadel-intel, Ollama primary + fallback, Gmail, Calendar, note-router, sheba) and per-run token & dollar usage.

Done when: every digest carries a live telemetry block with real error counts, per-service status, and token/$ for the day.

0.2 · Harden inference
Infra

Wrap Ollama calls in retry-with-backoff and a small queue so a timeout degrades gracefully instead of dropping to gemma noise. Resolve the port-8787 collision with the Octogent SSH listener. Give sheba a real health endpoint or formally retire the node.

Done when: a week passes with zero unhandled Ollama timeouts and no "sheba unreachable" phantom.

0.3 · Restore the audit substrate
Infra

Bring back the rich events.json schema retired on 28 April — the fact, risk, monitor-hit and opportunity registries — so the forensic scorecard can be computed from data rather than re-read from prose.

Done when: a day's scorecard can be generated from sidecar data with no manual reading.

0.4 · Runtime & CI
Infra

Migrate off end-of-life Python 3.9.6 to 3.12; clear the Google-library and urllib3 deprecations; fix the two date-fixture tests so the Briefing-Room suite is green in CI.

Done when: 3.12 in production and the test suite passes 145 / 0 / 0.

Exit gate · Phase 0

The dashboard reports true error counts, real per-service health and token/dollar usage; inference no longer silently falls back; the runtime is supported and the suite is green. Only then does Phase 1 begin.

Phase 1
Phase 1 · Weeks 2–4 · 26 Jul – 15 Aug

The control plane.

One canonical matter registry — the artefact everything else hangs from.
1.1 · The matter registry
Farhad · Brandon

Build the single source of truth the doctrine mandates: one row per live matter, eleven fields — Matter ID, category, stage, risk tier, value tier, deadline (NZT), next action, routing rule, source-of-truth link, human owner, automation coverage. It is a file (and its Notion twin), not a briefing.

Done when: every live matter across all projects and fronts has a row; nothing lives only in an inbox or a head.

1.2 · Taxonomy & risk/value matrix
Farhad

A fixed category taxonomy (project / tax / litigation / finance / regulatory / entity / acquisition) and a risk×value matrix so triage is rule-based, not vibe-based. This is what lets the routing engine in Phase 2 decide anything.

Done when: every registry row carries a taxonomy tag and a risk/value cell.

1.3 · Matter IDs on every output
Infra · Zach

Stamp the registry's matter IDs onto daily briefings, event sidecars and captures, so a line in a digest links back to a canonical matter — the end of "which McLean's thing is this?"

Done when: briefing line items resolve to a matter ID and back to the registry.

1.4 · The weekly rollup
Farhad · Brandon

A Monday operating review generated from the registry — what moved, what is overdue, what is at risk, what needs a decision — replacing the memory-based Monday.

Done when: the first registry-driven weekly rollup runs and is used to run the week.

The eleven fields

  • Matter ID
  • Category (taxonomy)
  • Stage
  • Risk tier
  • Value tier
  • Deadline (NZT)
  • Next action
  • Routing rule
  • Source-of-truth link
  • Human owner
  • Automation coverage

Seed set · day one

Backfill from what the reports already surfaced: Hyperion DOCA, the NOPA entities, ERA 3407924, Police v Moinfar, McLeans, RYU Albany, Babich Rise, 126 Featherston, Castra suite, the SPV register, the acquisition pipeline. ~40 live matters exist today — none are in a registry.

Why this is load-bearing

Without it the machine can brief and remind but cannot run a review, route a decision, or catch a slipping matter. It is the difference between a cockpit and a control plane — and the doctrine's first instruction.

Phase 2
Phase 2 · Weeks 4–8 · 11 Aug – 5 Sep

Routing, playbooks & governance.

Decisions get routed; the risky ones escalate to a human; the machine gets guardrails.
2.1 · The routing engine
Infra · Farhad

Four hard paths on every registry item — auto-execute · draft-for-review · escalate-to-human · route-external — with mandatory escalation triggers (see facing page). The machine stops deciding what only a human should.

Done when: each registry row resolves to one of four routes, and every escalation trigger fires a human review.

2.2 · Tranche-1 playbooks
Farhad · Brandon

The three highest-frequency six-component playbooks the doctrine names: IRD / Authority, Property Transaction, and Finance Application — each a repeatable sequence the machine can drive and a human can sign.

Done when: a live matter in each class is run end-to-end through its playbook.

2.3 · Stella guardrails & privacy
Farhad · Counsel

Confirmation gates before any external send or disclosure; a deny-list on financial/calendar detail after the June data-disclosure incident; the IPP 3A / Privacy Act review the three production agents still need.

Done when: no agent can send or disclose externally without a gate, and the privacy review is signed off.

Mandatory escalation triggers

Escalate
Any contact with a regulator (IRD, ERA, Police, Councils, Commissioners).
Escalate
Any exposure or commitment over $100k.
Escalate
Any police, court or statutory-demand matter.
Escalate
Any settlement or admission of liability.
External
Any indemnity over $50k → external counsel review.

The trust rule, written down

The machine surfaces; counsel and the operator decide. After the "over-caffeinated AI" episode and the Hyperion mis-brief, this is doctrine, not preference: no AI-set strategy on any live legal or financial matter.

Phase 3
Phase 3 · Weeks 8–11 · 1 – 30 September

Monitors, Notion & scale to 5×.

Autonomous watchers on top of the registry; structured state live; leverage measured.
3.1 · The six monitors
Infra · Zach

Deploy the doctrine's six autonomous monitors against the registry — Project Pulse first, because it is the one that would have caught seven weeks of Trojan slippage. Then Deal Flow, Gazette/Regulatory, Counterparty, Obligation and Inbox Sentiment.

Done when: all six emit daily to the dashboard, and Project Pulse flags any matter unmoved past its SLA.

3.2 · Un-freeze Notion
Farhad · Zach

Wire the registry to write structured state back into Notion so the Trojan databases stop being a pristine 5-May fossil — or, if that can't be kept live, formally retire the "structured state → Notion wins" claim. A database nobody writes to is worse than none.

Done when: Notion reflects registry state within a day, continuously — or the claim is retired in writing.

3.3 · Research desk, back on cadence
Zach

Restart the Perplexity → reviewer pipeline that went quiet after 11 June, with a per-brief cost cap and the reviewer's ship/revise/reject gate intact. Make claimed deliverables (render sets, packs) land as files, or stop claiming them in digests.

Done when: briefs resume on a set cadence with logged cost, and every claimed artifact is a file on the drive.

The 5× arithmetic

Baseline (March audit): ~2.8× multiplier, ~15% automation coverage. Target: 5.0×, 65%+ coverage. The lever is not more briefings — it is routing (auto-execute the safe, draft the routine) and playbooks (repeat the known). Coverage is measured off the registry's automation coverage field.

Monitors, in priority order

  1. Project Pulse — slippage
  2. Obligation — deadlines & payments
  3. Gazette / Regulatory
  4. Counterparty intelligence
  5. Deal Flow
  6. Inbox Sentiment

Exit gate · Phase 3 — GREEN

Six monitors live, Notion reflecting the registry, research desk on cadence with cost telemetry, and the scorecard on the next page reading GREEN across every line. Leverage measured at or above 5×.

Risks to the plan

High
Operator bandwidth. The same person runs the deals and the build. If deal-tempo spikes, the registry slips. Mitigant: time-box Phase 1 to the registry only; defer everything else.

Registry rot. A registry no one updates is Notion all over again. Mitigant: the weekly rollup reads from it, so it must be current to be useful.
